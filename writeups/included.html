Hack The Box — Included

Een compacte technische write-up over een aanvalsketen waarin een onbeveiligde TFTP-service, credential reuse en te ruime LXD-rechten uiteindelijk leiden tot volledige systeemtoegang. Flags, doel-IP-adressen en wachtwoorden zijn bewust weggelaten.

Difficulty: Very Easy OS: Linux Focus: TFTP • Web • LXD
WRITE-UP SECTIONS Overview Recon Enumeration Initial Access Privilege Escalation Attack Path Lessons Learned

Overview

In deze lab lag de focus voornamelijk op web enumeration, TFTP, credential reuse en privilege escalation via LXD.

Recon → Enumeration → Initial Access → Privilege Escalation

Reconnaissance

Ik begon de machine met mijn Superscanv2-workflow.

PortServiceWaarom interessant?
80/tcpHTTPWebapplicatie aanwezig
69/udpTFTPBestandsoverdracht zonder gebruikersauthenticatie

De combinatie van een webserver en een onbeveiligde TFTP-service was direct interessant, omdat beide services mogelijk toegang hadden tot dezelfde bestanden.

Enumeration

Tijdens verdere enumeratie ontdekte ik een actieve TFTP-service:

  • Geen authenticatie: de TFTP-service accepteerde aanvragen zonder gebruikersauthenticatie.
  • Schrijfrechten: bestanden konden naar de TFTP-root worden geschreven.
  • Gedeelde webroot: de TFTP-root bleek gekoppeld aan /var/www/html/, de webroot van de HTTP-service.
De belangrijkste aanwijzing was dat een bestand dat via TFTP werd geplaatst, vervolgens via de webserver bereikbaar kon zijn.

Initial Access

Uit de enumeratie bleek dat de combinatie van ongeauthenticeerde TFTP-schrijfrechten en een actieve PHP-webserver kon worden misbruikt om server-side code in de webroot te plaatsen.

TFTP upload → PHP webshell → toegang als www-data

Nadat de webshell via HTTP werd aangeroepen, verkreeg ik initiële toegang als de beperkte webservergebruiker www-data.

Credential Discovery

Tijdens inspectie van de webroot werden .htaccess en .htpasswd aangetroffen. Het .htpasswd-bestand bevatte bruikbare authenticatiegegevens. Zonder het wachtwoord te publiceren, kon ik hiermee lokaal overschakelen naar de interactieve gebruiker mike. 

www-data@included:/var/www/html$ su mike
Password: [REDACTED]
mike@included:/var/www/html$

Privilege Escalation

Na toegang als mike begon ik met lokale enumeratie. Daarbij controleerde ik onder andere groepslidmaatschappen, sudo/SUID-rechten, services, configuratiebestanden en geplande taken.

De belangrijkste ontdekking was dat de gebruiker lid was van de lokale LXD-groep. Dit groepslidmaatschap gaf voldoende rechten om een geprivilegieerde Linux-container te starten en de root-bestandsstructuur van de host daarin te koppelen.

Via deze container kon de gekoppelde host-schijf met verhoogde rechten worden benaderd, waardoor uiteindelijk volledige root-toegang tot de host mogelijk was.

LXD group membership → privileged container → host filesystem → root

Attack Path

Superscanv2 / Nmap ↓ HTTP + TFTP identificeren ↓ TFTP-schrijfrechten bevestigen ↓ Webroot bereikbaar via TFTP ↓ PHP webshell ↓ Initial Access als www-data ↓ .htpasswd ontdekt ↓ Credential reuse → lokale gebruiker ↓ LXD-groepslidmaatschap ↓ Geprivilegieerde container ↓ Root Access

Wat ik hiervan heb geleerd

  • Service chaining: twee afzonderlijke services kunnen samen een bruikbaar aanvalspad vormen.
  • Credential reuse: credentials uit een webconfiguratie kunnen ook elders bruikbaar zijn.
  • Least Privilege: lidmaatschap van krachtige containergroepen kan praktisch root-equivalent zijn.
Deze lab liet goed zien hoe meerdere relatief kleine misconfiguraties samen kunnen escaleren tot volledige systeemovername. Vooral de relatie tussen services en lokale groepsrechten bleek bepalend voor de aanvalsketen.
